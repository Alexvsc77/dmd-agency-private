# DMD агенство 

## Запуск на Mac

1. Открой `Запустить DMD.command` двойным щелчком. Оставь окно терминала открытым.
2. Сайт: <http://127.0.0.1:8787>.
3. Админка: <http://127.0.0.1:8787/admin>.
4. При первом посещении админки создай логин и пароль (не менее 12 символов). Сохрани их в менеджере паролей. Дальше доступна только форма входа.
5. Для остановки нажми `Ctrl+C` в терминале.

Требуется Node.js 24 LTS или новее с `node:sqlite`. Скрипт использует установленный Node.js либо совместимый runtime Codex на этом Mac. Установка дополнительных npm-пакетов не нужна. Из терминала можно запустить `node server.mjs`.

Сервер слушает только `127.0.0.1`: эта версия предназначена для локальной проверки на одном компьютере. Открытие `dist/index.html` как файла позволяет посмотреть дизайн, но для отправки нужен адрес сервера выше. GitHub Pages не запускает этот сервер.


## Проверка

```sh
node --test test/server.test.mjs
```

Проверяется сохранение после перезапуска, повторная отправка без дублей, валидация, недоступность данных без входа, статусы, поиск, сессии и блокировка запросов с другого сайта.

Локальный Node.js-сервер не размещён в интернете. Для публичного сайта подключён отдельный облачный обработчик Supabase, описанный ниже.

## Облачная версия на GitHub Pages

Публичный сайт: https://alexvsc77.github.io/mrz-agency/
Админка: https://alexvsc77.github.io/mrz-agency/admin.html

Сайт на Pages использует отдельный бесплатный проект Supabase **DMD Agency** (`eqhuhaolwxvtinbgubxi`, eu-central-1). Адрес обработчика: `https://eqhuhaolwxvtinbgubxi.supabase.co/functions/v1/dmd-api`. На `localhost` и `127.0.0.1` обе страницы продолжают работать с локальным `server.mjs` и отдельной SQLite-базой. Локальные данные автоматически в облако не копируются.

- `supabase/schema.sql` содержит схему начальной установки. Не запускай её повторно поверх существующей базы. Изменения вносятся отдельными миграциями.
- `supabase/functions/dmd-api/index.ts` — обработчик без внешних npm-зависимостей. Он валидирует заявки, сохраняет серверные цены, ограничивает частоту отправок и защищает чтение и смену статуса проверкой Supabase Auth и таблицы `dmd_admins`.
- Edge Function развёрнута с `verify_jwt=false`, чтобы посетители могли отправлять обращения без аккаунта. Все маршруты с данными администратора проверяют токен самостоятельно через Supabase Auth. Отключение проверки на шлюзе не открывает чтение заявок.
- Прямой доступ `anon` и `authenticated` к таблицам и SQL-функциям отозван. RLS включён без разрешающих политик намеренно: доступ выполняется только сервером. Служебный ключ берётся из окружения Supabase и не находится в HTML или Git.
- Администраторов создаёт владелец проекта через Supabase Authentication → Users → Invite user. После приглашения добавь UUID пользователя в `public.dmd_admins.user_id` через панель Supabase. Только аккаунт, чья почта подтверждена и UUID добавлен владельцем, получает доступ.
- В Authentication → URL Configuration задай Site URL и разрешённый Redirect URL: `https://alexvsc77.github.io/mrz-agency/admin.html`. Получатель приглашения открывает письмо и задаёт пароль самостоятельно. В HTML нет публичной формы регистрации администратора.
- Облачная админка сохраняет только access token в `sessionStorage` текущей вкладки. Пароль не сохраняется. По истечении токена нужен повторный вход. Выход отзывает токен в приложении и завершает текущую сессию Supabase.
- Публичность HTML и Git-репозитория не даёт доступ к заявкам. Защита данных выполняется сервером.

Бесплатный тариф имеет лимиты; Supabase может приостановить проект после периода низкой активности. Восстановление — через панель Supabase. Это бесплатная начальная версия, без гарантии непрерывной доступности и без подключённых платных ресурсов.

Проверки: `node --test test/cloud.test.mjs test/server.test.mjs` (Node.js 24+).

Исходники полного проекта: `Alexvsc77/dmd-agency-private` (сейчас публичный по решению владельца). Для публикации клиентских страниц используются отдельная папка `../dmd-public/` и репозиторий `Alexvsc77/mrz-agency`, ветка `main`, корень. После правки HTML синхронизируй `dist/index.html` → `../dmd-public/index.html` и `dist/admin.html` → `../dmd-public/admin.html` и запушь соответствующие репозитории. Базы, пароли и служебные ключи не коммить.
